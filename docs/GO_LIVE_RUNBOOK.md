# راهنمای راه‌اندازی روی VPS (آماده‌سازی؛ اجرا نشده)

این سند فقط **آماده‌سازی** است. هیچ deploy، تغییر DNS یا روشن‌کردن رزرو/پرداخت/پیامک بدون درخواست صریح مالک انجام نمی‌شود. staging وجود ندارد؛ پس هر مرحله‌ی «اجرا» باید با دقت و با backup انجام شود.

## ۱. ساخت بسته‌ی انتشار

```bash
npm ci && npm run build            # روی کامیت تمیز main
python scripts/build-release-package.py --output .work/drzamani-release.zip
```

خروجی: `drzamani-release.zip` و `drzamani-release.manifest.json` (نسخه، کامیت، tree، sha256 هر فایل). بسته شامل `api/.env`، دیتابیس، آپلود یا node_modules نیست. sha256 فایل manifest را قبل از انتقال یادداشت کنید و روی سرور دوباره بسنجید.

## ۲. پیش از انتشار (روی سرور)

1. `deploy/preflight-vps.sh` را اجرا کنید و خروجی را بخوانید.
2. از دیتابیس **و** پوشه‌های `public-media` و `uploads` backup هماهنگ بگیرید (timer و jobها و API متوقف باشند). deploy قدیمی فقط SQLite را نگه می‌داشت؛ `release_manager.py` جدید snapshot هماهنگ می‌گیرد، ولی روی سرور واقعی هنوز آزموده نشده است.
3. فایل Nginx را با `deploy/nginx-drfarzadzamani.conf` مقایسه کنید. مدیر انتشار آن را خودکار نصب **نمی‌کند**. تغییرات این نسخه: `limit_req_zone drz_public`، محدودیت `/api/v1/availability`، فشرده‌سازی متن (بدون JSON)، کش `immutable` فقط برای `/assets/`، کش ۷ روزه برای تصاویر.
4. `ENV` سرور را با `deploy/env.production.example` مقایسه کنید (پیامک `disabled`، رزرو `false`، کلید رمزنگاری تنظیمات مستقل از `SECRET_KEY`).

## ۳. انتشار

`sudo deploy/deploy-release.sh /path/drzamani-release.zip`

Migrationهای `20261004_0020` تا `20261005_0023` (خدمات، متن صفحه اصلی، نمونه‌کارها، و مجوزهای مقاله/نظر/رسانه برای نقش مدیر) خودکار اجرا می‌شوند. داده‌ی اولیه هنگام اولین راه‌اندازی ساخته می‌شود: ۴ صفحه‌ی خدمت، پنج بلوک متن (hero، trust، about، faq، footer) و ۱۶ تصویر قدیمی نمونه‌کار؛ همان ظاهر قبلی.

## ۴. پس از انتشار

- `/api/health` باید JSON با نسخه‌ی درست بدهد؛ `/`، `/services/`، `/articles/`، `/appointment/` (صفحه‌ی بسته‌بودن رزرو)، `/sitemap.xml` را در مرورگر بازدید کنید.
- نقش‌های پیش‌فرض مجوزهای تازه را خودکار می‌گیرند (`docs/ROLES.md`)؛ در پنل کارکنان یک ادمین آزمایشی بسازید و دسترسی‌اش را ببینید.
- با حساب مدیرکل: عوض‌کردن رمز، فعال‌سازی رمزساز (MFA)، و بررسی `نقش‌ها و کارکنان`.
- بازنگری متن‌ها: خدمات، متن‌های صفحه اصلی (شامل ۱۵٬۰۰۰ جراحی و ۲۰ سال تجربه)، مقالات و نظرات باید پزشک تأیید کند؛ نمونه‌کارهای قدیمی بدون سابقه‌ی رضایت‌نامه در سیستم هستند و مالک باید رضایت را جدا مستند کند.

## ۵. بازگشت

`deploy/rollback-release.sh` فقط **کد** را برمی‌گرداند و migration را برنمی‌گرداند. اگر انتشار شکست خورد و دیتابیس تغییر کرده، از backup همان لحظه (دیتابیس + رسانه) بازیابی کنید؛ downgrade دستی migration فقط با backup. در `docs/PHASE_10_RECOVERY.md` توضیح کامل آمده است.

## ۶. گیت‌های باز (انجام نشده)

DNS/TLS واقعی و Cloudflare، حساب Turnstile/Google، فراهم‌کننده‌ی پیامک و پرداخت واقعی (فقط با حساب آزمایشی و دستور مالک)، هویت بسته در production، backup خارج از میزبان، آزمون قطع برق. این‌ها در `docs/PHASE_10_ACCEPTANCE.md` ثبت‌اند.
