## چیزهایی که نباید اشتباه فرض شود

- ممیزی کامل و اجرای برنامه هنوز انجام نشده؛ PASS هیچ تستی ادعا نشده است.
- یکتایی `Appointment.payment_id` وجود دارد. callback نیازمند بررسی race/state است؛ ادعای دو ردیف ثبت‌شده را بدون بازتولید تکرار نکن.
- SMS outbox وجود دارد ولی dispatch در callback synchronous است؛ همان زیرساخت را کامل کن.
- ClinicSetting، API و پنل اطلاعات مطب موجودند؛ به‌جای ساخت موازی، تکمیلشان کن. SEO build-time ممکن است بعد از ذخیره قدیمی بماند.
- /articles در Nginx عمداً 410 است؛ مقاله‌های حذف‌شده قبلی را خودکار برنگردان.
- توکن‌ها localStorage هستند و نقش‌ها عمدتاً admin/secretary با چک ثابتند.
- تطبیق نسخه live با source تأیید نشده؛ خطای ابزار شبکه را خرابی سایت گزارش نکن.

## اجرا و محدودیت محیط

- README دستورهای اجرا را دارد؛ Node >=22.22، Python >=3.12,<3.14 و uv. frontend: `npm.cmd ci` و `npm.cmd run dev`؛ backend از داخل api: `uv sync --frozen`، ENV توسعه صریح، migration و uvicorn.
- برای اجرای مرحله 1 از DB تست مستقل و providers ساختگی/console استفاده کن؛ jobs، SMS واقعی، پرداخت واقعی و DB بیماران وارد آزمون نشوند.
- تست `api/tests/test_api.py` در import از drop_all/create_all استفاده می‌کند؛ قبل از pytest حتماً config دیتابیس موقت را بررسی کن. conftest فعلی DB آزمایشی را تعیین می‌کند.
- Git با schannel در این محیط خطای SEC_E_NO_CREDENTIALS داد؛ `git -c http.sslBackend=openssl ...` موفق شد. sslVerify را خاموش نکن.
- gh روی PATH نبود؛ ابزار اتصال GitHub خواندن/نوشتن داشت. secret/token از کاربر در چت درخواست نکن.
- نمایش فارسی PowerShell گاهی ? بود ولی فایل خام سالم است؛ از روی نمایش ترمینال تصمیم به اصلاح encoding نگیر.
- دسترسی سایت با ابزار web/curl موفق نشد؛ تست‌های runtime نیز در این تحویل اجرا نشده‌اند.
