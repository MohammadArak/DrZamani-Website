تاریخ: 2026-10-16، Asia/Tehran. مبنا نسخهٔ 1.19.3 روی main با commit `0072d69568f7512ba4f8507611f99dc6c5f75c6b` است؛ PR26 و PR27 با پنج بررسی موفق ادغام شده‌اند. این گزارش فقط آزمون‌های تازه را توصیف می‌کند. نتیجهٔ آنلاین ادغام و CI از گیت‌هاب و رسید تحویل همان نسخه خوانده شود.

## قرارداد حذف دائمی

این قابلیت فقط برای مدیرکل است. حساب فعلی قابل حذف نیست؛ پیش از purge باید حساب به حذف‌شده‌ها منتقل شده باشد و نام کاربری دقیقاً تأیید شود. حساب، نقش‌های انتسابی، نشست‌ها و اطلاعات MFA وابسته حذف می‌شوند. سابقهٔ بیمار، پیام، مالی و لاگ‌های قابل نگهداری حذف نمی‌شوند؛ FKهای مربوط از سیاست تعریف‌شدهٔ SET NULL پیروی می‌کنند. اگر حساب مالک محتوا یا مرجع محدودکنندهٔ دیگری باشد، API با 409 حذف را رد می‌کند؛ این endpoint مالکیت نوشته را به فرد دیگری نسبت نمی‌دهد و تاریخچهٔ محتوا را نابود نمی‌کند. نقش پیش‌فرض سیستم یا دارای عضو حذف نمی‌شود؛ نقش سفارشی بدون عضو از مسیر موجود قابل حذف است.

آزمون مرورگر، guard تایپ و لغو حذف دائمی را بررسی کرد؛ دکمهٔ نهایی purge از مرورگر اجرا نشد. حذف دائمی واقعی فقط در آزمون API روی حساب‌های موقتِ همان تست اجرا شد. آزمون، ابطال نشست و حفظ لاگ قبلی، منع نقش‌های غیرمدیرکل و جلوگیری از حذف نویسندهٔ دارای مقاله را سنجید.

## شواهد و حد آزمون

- کامل بک‌اند محلی: **451 passed،16 skipped،4 warnings،263.97s**. تست نقش‌ها 68 پاس و تست بستهٔ محتوا 11 پاس هستند و با مجموعهٔ کامل هم‌پوشانی دارند؛ با هم جمع نشوند. تست محتوا پس از ویرایش منابع اجرا شد.
- lint بدون هشدار، build/version، transport، بودجه، proxy، فونت، چت و Ruff بحرانی اجرا شدند؛ سقف بودجه یا سیاست امنیتی برای عبور تست ضعیف نشد. نتیجهٔ دقیق نهایی اندازه‌ها در `bundle-1.19.4.json` همراه خروجی است.
- migration خالی و دارای داده، downgrade/re-upgrade، integrity و foreign_key_check موفق شدند. اولین روش batch روی جدول کارکنان دارای FK شکست خورد؛ migration اصلاح‌شده از ADD/DROP COLUMN بومی استفاده می‌کند و دوباره پذیرفته شد.
- `BROWSER-ACCEPTANCE-1.19.4.json`،`ARTICLE-SOURCES-1.19.4.json`،`CLEAN-INSTALL-1.19.3.json` و رسید نصب بستهٔ نهایی شواهد مستقل‌اند. شبکهٔ معیوب روی ASGI محلی تزریق شد؛ این آزمون قطع اینترنت واقعی گوشی نیست.
- نصب مستقیم فایل‌های Python در این میزبان timeout داد. ۴۲ wheel از mirror دریافت و هر SHA256 با uv.lock اصلی تطبیق داده شد؛ venv تازه از همان فایل‌های قفل‌شده نصب شد. خطای دسترسی کش قدیمی TypeScript/Vite با اجرای مجاز دارای دسترسی لازم رفع شد؛ به‌عنوان خرابی محصول یا PASS جعلی ثبت نشد.
- بعد از ساخت جدید، تب باز با chunk قدیمی باید reload شود. در طول QA این حالت رخ داد و پس از reload رفع شد. این مشاهده، پذیرش به‌روزرسانی production یا حفظ همهٔ دارایی‌های نسخهٔ قبلی را ثابت نمی‌کند.
